# Data annotation and evaluation guide

How to build an evaluation set that is allowed to support a quality claim, and
what "quality claim" means here.

The harness refuses to report a rate unless the manifest satisfies all of:
real footage, `VERIFIED` labels, ≥20 real clips, ≥5 independent source groups.
That refusal is the point — a number produced from synthetic clips or from one
self-labelled event is a measurement of the labelling, not of the detector.

## 1. Label unit: the EVENT

Labels are **event-level**, in seconds on the media timeline:

```json
{ "kind": "accident", "start_seconds": 12.4, "end_seconds": 15.8,
  "subtype": "rear_end", "verified_by": "name/date" }
```

A prediction counts as a true positive when its incident start falls inside a
labelled window. Frame-level labelling is **not** supported and should not be
attempted: consecutive frames are near-duplicates, and frame-level splits leak
the same event across train and test, which is the single most common way a
video metric is made meaningless.

## 2. What counts as an accident (`kind: "accident"`)

A collision or overturn involving at least one vehicle where **damage or a
disruption is visible in the frames** — not merely "two cars were near each
other".

| Label | Yes | No |
|---|---|---|
| Two vehicles in contact with a visible abrupt stop/rotation | ✅ | |
| Vehicle mounts a kerb and comes to rest on the carriageway | ✅ | |
| Vehicle overturns | ✅ | |
| Vehicles drive close at low speed in adjacent lanes | ❌ | hard negative |
| Near miss, no contact, both continue normally | ❌ | hard negative |
| Camera shake, lens splash, compression artefact | ❌ | hard negative |

### `subtype` vocabulary (keep it closed, add to it in review)

`rear_end` · `head_on` · `side_impact_t_bone` · `rear_end_into_stationary` ·
`rollover` · `kerb_mount` · `pedestrian_struck` · `two_vehicle` ·
`unclassified_collision` (use this, then review; do not guess a subtype)

## 3. Hard negatives — as important as positives

A system is judged on what it *does not* alert on. Collect at least as many
negatives as positives. Each must be labelled `normal` at clip level and should
carry a `hard_negative` event marking the moment the system would plausibly be
tricked.

| Hard negative | Why it fools the tracker / motion analyser |
|---|---|
| `hard_braking` | large deceleration without contact |
| `close_following` | small inter-vehicle gap, converging trajectories |
| `parked_vehicles` | many stationary objects → overlap and proximity |
| `pedestrian_crossing` | person enters the vehicle path, no contact |
| `lane_change` / `merging` | rapid lateral motion, TTI spikes |
| `camera_pan` / `camera_mount_shake` | global motion compensation must subtract it |
| `occlusion` | objects disappear behind a bus/pole, ids churn |
| `rain` / `night` / `glare` / `fog` | detector confidence collapses |
| `construction_zone` / `cones` / `barriers` | many small objects, high object count |
| `oncoming_traffic_opposite_lanes` | converging in image space, safe in reality |
| `emergency_vehicle_siren` | legitimate fast motion |
| `loading_unloading` | stopped van, doors open, people around |

A negative clip that contains a `hard_negative` window is far more informative
than one that is quietly empty.

## 4. Label quality grades (required field)

| Grade | Meaning | Supports a quality claim? |
|---|---|---|
| `VERIFIED` | a person watched the event and confirmed it is what it claims | **yes** |
| `OPERATOR` | a domain expert asserted it; not independently reviewed | no |
| `PROVISIONAL` | inferred — e.g. located from the pipeline's own output | **no — circular** |
| `SYNTHETIC` | generated by this project | **no** |

`PROVISIONAL` labels derived from the system's own output are circular by
construction: the system is being graded against itself.

## 5. `source_id` — the leakage group

Every clip from the same recording session, camera, junction, or contiguous time
block shares one `source_id`. The splitter keeps a group entirely on one side,
so near-duplicate footage cannot straddle a split.

```
good:  CAM-03/junction-North/2026-03-14-am  -> one source_id for all 40 clips
bad:   every clip gets its own source_id  -> 40 "independent" samples that are
                                             really the same 3 minutes
```

Split guidance: group by `source_id` first, then stratify by class, seeded
(`--seed`) so the split is reproducible. Verify with the `leakage check` line in
the report — it must read `PASS`.

## 6. Minimum set before any claim

| Requirement | Minimum |
|---|---|
| real clips | ≥20 (target 50+) |
| independent `source_id` groups | ≥5 (target 10+) |
| distinct cameras/locations | ≥5 |
| positives / negatives | roughly balanced; record the ratio |
| positives per split partition | ≥5, and ≥20 clips in the test partition |
| hard-negative categories covered | ≥6 of the table in §3 |

The harness prints `split_sufficiency` and refuses the claim when these are not
met. That is intentional friction.

## 7. Commands

```bat
:: inspect a manifest and its blockers, without running inference
python scripts\evaluate.py --describe-only

:: full reproducible evaluation
python scripts\evaluate.py --manifest evaluation\manifest.json --out reports\eval.json

:: a specific split seed (record it alongside the result)
python scripts\evaluate.py --manifest mine.json --seed 12345
```

The evaluation forcibly disables the notification subsystem, so an evaluation
run can never place a call or send a message.

## 8. Reading the output honestly

* **Precision 1.000 with n=1 is not perfect precision.** Read the CI: the report
  prints `precision 1.000 [95% CI 0.206-1.000] n=1`.
* **PR-AUC is undefined without positives**; the harness returns `None` and says
  so rather than printing a number.
* **Raw `accident_score` is an uncalibrated evidence index**, not a probability.
  Do not write "44% chance of an accident" without a calibration report
  (reliability curve + ECE) on a real labelled set.
* **Cost asymmetry is not symmetric.** A false negative (missed crash) is far
  worse than a false alarm. The suggested threshold maximises F1 as a neutral
  default and says so; adjust deliberately.
